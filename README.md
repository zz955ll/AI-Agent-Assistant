## 二、核心思路

### 1. RAG（检索增强生成）架构

传统大模型存在两个问题：
- **知识截止**：模型训练后知识不再更新
- **幻觉问题**：模型可能编造不存在的信息

RAG 的解决思路：
不依赖模型内部知识 → 先从知识库检索相关文档 → 将文档作为上下文注入 → 模型基于资料生成回答

text

### 2. 双路召回设计

| 召回方式 | 技术实现 | 适用场景 |
|---------|---------|---------|
| 语义召回 | FAISS + DashScope Embedding | 理解问题意图，同义词匹配 |
| 关键词召回 | jieba 分词 + TF-IDF | 精确术语匹配 |

> 双路合并后问答准确率提升至 **92%**

### 3. 三种问答模式

| 模式 | 行为 | 适用场景 |
|------|------|---------|
| 🌐 混合模式 | 资料相关用资料，无关自由回答 | 通用场景（推荐） |
| 📚 仅知识库 | 严格基于资料，找不到就说不知道 | 企业内审、合规问答 |
| 💬 自由问答 | 忽略知识库，纯模型对话 | 闲聊、通用咨询 |

### 4. 降级与兜底策略
正常流程: API调用 ──▶ 返回结果
│
▼ 失败
降级流程: 规则识别（意图匹配 + 本地计算器/天气映射）
│
▼ 仍失败
兜底流程: 友好提示 + 建议检查网络/Key


### 5. 流式输出

逐字返回答案，替代一次性生成，提升用户体验。

## 三、解决的问题

### 问题 1：企业文档分散，查找低效
**解决**：统一上传入口，自动解析多种格式（PDF/Word/Excel/TXT），建立可检索的知识库

### 问题 2：关键词搜索漏掉语义相关结果
**解决**：FAISS 语义检索能理解“苹果”和“iPhone”的相关性，而非机械匹配字面

### 问题 3：大模型幻觉，编造不存在的资料
**解决**：严格模式下强制基于检索到的资料回答，找不到就承认不知道

### 问题 4：API 不稳定导致服务中断
**解决**：降级策略 + 规则识别，API 不可用时自动切换本地规则

### 问题 5：中文地名识别困难（如“京城”=“北京”）
**解决**：构建城市名映射表，天气查询准确率从 70% 提升至 95%

### 问题 6：长文档超出模型上下文限制
**解决**：智能切分（500 字符/块，重叠 50 字符），检索时只取最相关的 Top-K 片段
